## 1. 도메인 확정 (명세 2.1)

**도메인: 주택담보대출 (내집마련)** — 2회차 대출 상품 RAG 도메인을 이어 간다.

| 조건 | 근거 |
| :--- | :--- |
| 외부 API 3종 이상 | ① 금감원 금융상품한눈에(상품 목록·금리 옵션) ② 국토교통부 아파트 매매 실거래가(지역 시세) ③ 카카오 로컬(은행 지점 위치) — 서로 다른 기관, 서로 다른 정보 |
| 출처·이용 조건 | [sources.md](../sources.md) (호출 한도, 약관 요점) |
| 제약 비교가 필요한 요청 3개 이상 | 아래 2절 R1~R4 — 공시 금리로 월 상환액을 계산해야만 "월 ○만원 이하"를 판단할 수 있다 |
| 저장·조회·수정·삭제할 결과물 | 은행 상담 계획 (상품, 날짜, 시작·종료 시각, 대출 조건) |
| 위험 도메인 여부 | **금융 — 위험 도메인.** 모든 화면·응답에 "본 서비스는 정보 제공용이며 금융 전문가의 조언을 대신하지 않습니다." 와 금감원 출처 문구 표시 |

**LLM 만으로 답하면 틀리는 것** (기획 검증 2.7)

| 요청 | Tool 없이 LLM 만 답하면 |
| :--- | :--- |
| R1 조건에 맞는 주담대 찾기 | 현재 공시되지 않은 상품명·금리를 지어내고, 월 상환액을 어림셈해 상한 판단이 틀린다 |
| R2 고정금리·빠듯한 상한 | 대안 권역(보험·저축은행) 상품의 실제 금리를 알 수 없어 "없다" 또는 근거 없는 추천을 한다 |
| R3 집값 미입력, 지역만 | 그 지역의 최근 실거래 시세를 모르므로 필요 대출금을 정할 수 없다 |
| R4 상담 지점 | 실제 지점 주소·전화·지도 링크를 모른다 |

## 2. 서비스 시나리오 (명세 2.2)

요청 분류: **plan**(대출 계획 수립) · **fact**(사실 조회: 시세·특정 회사 금리·지점) · **save**(계획 확정·저장) · **term**(용어 질문, 심화) · **other**(인사·사용법)

조건 분류 (`backend/app/agent/conditions.py`)

| 분류 | 항목 |
| :--- | :--- |
| 기준 조건 | 집값, 지역(서울 구), 보유 자금, 대출 희망액, 대출 기간, 상담 날짜·시각 |
| 선호 조건 | 금리 유형(고정/변동), 권역, 금융회사, 담보 유형 — 재계획 때 풀 수 있다 |
| 제약 조건 | 월 상환액 상한, 월 소득 + 소득 대비 상환 비율 상한 — 풀지 않는다 |

| # | 대표 요청 | Tool 순서 | 특징 |
| :--- | :--- | :--- | :--- |
| R1 | 마포구 6억 아파트, 현금 2억, 월 200만원 이하 주담대 | 시세 → 후보 → 상세×N → 지점 | 한 번에 충족 |
| R2 | 같은 조건 + 고정금리, 월 180만원 이하 | 시세 → 후보(은행) → 상세 → **재계획**: 금리 유형 완화 → 후보(보험) → 상세 → 지점 | 재계획 2회 |
| R3 | 같은 조건, 월 100만원 이하 | … 재계획 3회(보험·저축은행·여신전문) | 상한 도달 → 역산 기준 제시, 조건 조정 되묻기 |
| R4 | R1 + 카카오 키 없음 | 지점 검색만 `INVALID_KEY` | Tool 하나 실패, 나머지 정상 |
| R5 | 안녕하세요 | 없음 | Tool 불필요 |
| R6 | 월 150만원 이하 주담대 (자금·집값 없음) | 없음 | Tool 부르기 전에 되묻기 |
| R7 | R1 → "월 190만원으로 바꿔줘" → "1번으로 토요일 2시 저장" | 후속 요청은 바뀐 조건만 갱신 | 맥락 유지, 저장 |

**저장할 결과물의 핵심 값**: 제목, 상품(금융회사·상품명·식별자), 지점, 상담 날짜, 시작·종료 시각, 대출금·기간·금리 유형·상환 방식·금리·월 상환액, 메모, 생성·수정 일시.
**같은 날짜 시간 겹침**: 저장은 막지 않고, 겹치는 계획(번호·제목·시각)을 저장 결과와 함께 알린다. 종료 시각을 말하지 않으면 시작 + 60분(`agent.consult_minutes`)으로 정하고 그 사실을 응답에 밝힌다.

## 4. 기획 검증 결과 (명세 2.7)

| 항목 | 방법 | 결과 |
| :--- | :--- | :--- |
| 외부 API 3종 호출 | `python scripts/check_apis.py` (로컬 PC, 실제 키) | **미확인** — 클라우드 개발 환경에서 외부 API 가 막혀 있어 로컬에서 실행 후 결과를 적는다. 금감원·국토부는 2회차에서 같은 엔드포인트 호출을 확인함 |
| 실제 응답 ↔ Tool 출력 구조 | 같은 스크립트가 출력 키가 채워지는지 출력 | **미확인** (위와 같음). 픽스처는 2회차 실제 응답 구조(baseList/optionList, XML item 태그)를 따름 |
| 값이 비거나 결과 없음 | 금리 옵션 없는 상품 → `NO_RATE`, 거래 없는 조건 → `NO_RESULT`, 지점 없음 → `NO_RESULT` | 테스트로 확인 (`test_tools.py`). 실제 응답 확인은 미확인 |
| 호출 한도 확인 | 약관·포털 화면 | 금감원·국토부 확인(2회차). 카카오 일일 쿼터는 **확인 필요** |
| LLM 1회 호출, Tool 선택 | `check_apis.py` 마지막 단계 (Tool 명세를 넘겨 `tools` 출력 확인) | **미확인** (GMS 키 필요) |
| 설계 시험 (R1 을 단계대로) | `scripts/run_scenarios.py --fake` | 통과(연습용). 각 Tool 입력이 분석 결과(지역·권역)나 앞 Tool 결과(product_id, 1순위 회사)로 모두 채워짐 |
| 재계획 조건·상한 | R2·R3 | 통과(연습용). 재계획 2회 후 충족 / 3회 후 멈춤 |

**설계 시험에서 바꾼 것**
- 지점 검색을 처음에는 사용자 지역의 은행 전체로 하려 했으나, 판단 뒤 1순위 금융회사로 검색하도록 미룬 단계(`deferred`)로 바꿨다.
- 보험사 이름이 "삼성생명보험주식회사"처럼 길어 지점 검색이 비어서, 검색어에서 "주식회사"·"보험"을 떼도록 했다.
- 기간을 말하지 않으면 계산할 수 없어 처음엔 되물었지만, 대부분 30년을 전제로 묻기 때문에 설정 기본값 30년으로 계산하고 응답에 "기본값"임을 밝히도록 바꿨다 (요청 분석 결과에는 넣지 않음).
