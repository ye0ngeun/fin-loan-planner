## 0. 확인 방법과 현재 상태

| 확인 수단 | 무엇을 증명하나 | 상태 |
| :--- | :--- | :--- |
| 자동 테스트 `cd backend && python -m pytest -q` | 픽스처(가상 응답)와 규칙 기반 LLM 대역으로 요구사항 동작 | **68개 통과** (test_tools 23, test_agent 21, test_api 17, test_judge 7) — 2026-11-20 |
| 연습용 시나리오 `python scripts/run_scenarios.py --fake` | 대표 요청 7건의 응답·이벤트 전체 | 생성됨 → [docs/samples/scenarios.md](samples/scenarios.md) |
| 연습용 서버 + 브라우저 | 세 화면이 API 를 불러 표시, 실행 과정·재계획 표시 | 클라우드에서 Playwright 로 확인 (콘솔 오류 0). 제출용 캡처는 로컬에서 다시 찍는다 |
| 실제 키로 외부 API·GMS 호출 | 기획 검증, 실제 응답 구조, 처리 시간 | **미확인** — 클라우드 개발 환경에서 외부 API 가 막혀 있음. 로컬에서 `scripts/check_apis.py`, `scripts/run_scenarios.py` 실행 후 이 문서를 고친다 |

> 결과 기입 기준(셀프 체크리스트): 확인하지 않은 것을 통과로 적지 않는다. 아래 "픽스처" 열은 자동 테스트로 확인한 것이고, "실제 환경" 열은 실제 키·화면으로 확인해야 하는 것이다.

## 4. 로컬에서 할 일 (제출 전)

1. `.env` 에 네 키를 넣고 `python scripts/check_apis.py` → 결과를 [요구사항 정의서 4절](01_요구사항정의서.md#4-기획-검증-결과-명세-27)에 적는다.
2. `python scripts/run_scenarios.py` → 실제 처리 시간·차이를 2절에 적는다. 픽스처 기대와 다르면 원인과 수정 내용을 적는다.
3. 서버를 띄워 화면 캡처: 대화(추천·실행 과정), 재계획 표시, 계획 관리(겹침 표시·수정·삭제), 실행 로그 상세, `/docs` 목록(실행 로그 수정 API 없음), 키를 비운 상태의 안내, 네트워크 탭의 API 호출. `docs/screenshots/` (git 제외).
4. `LOGGING_AGENT=0` 으로 서버를 띄워 대화가 되고 실행 로그가 쌓이지 않는지 확인한다.
5. 셀프 체크리스트 엑셀에 위 표를 옮겨 적는다. "실제 환경" 이 미확인인 칸은 통과로 적지 않는다.
